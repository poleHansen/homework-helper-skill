# 作业批量批改

## 输入

用户需要提供：

1. **评分要求文档**：docx/pdf，写明各评分点及分值（如"实验目的 5 分、功能模块图 15 分"）
2. **作业压缩包**：zip，内含全班作业，支持 `.docx` / `.pdf`

可选：输出目录（默认当前目录下的 `批改结果/`）。

## 工作流

设 `W` 为工作目录（如 `批改结果/`），脚本位于本 skill 的 `scripts/` 目录。

### 第 1 步：解压

```bash
python scripts/prepare.py <压缩包> <W>
```

生成 `W/submissions/`（原件）和 `W/manifest.json`（清单）。清单里的 `skipped` 会列出格式不支持的文件，需在最终汇总里说明。

### 第 2 步：拆评分点

读评分要求文档，抽出结构化评分表写入 `W/rubric.json`：

```json
{
  "title": "实验一",
  "max": 100,
  "items": [
    {"title": "实验目的", "max": 5, "criteria": "是否说明目的、是否结合本次任务"},
    {"title": "功能模块结构图", "max": 15, "criteria": "结构完整、层次清晰、模块划分合理"}
  ]
}
```

`criteria` 写清扣分依据，后续每份作业都按同一标准判分——这是全班分数可比的前提。

### 第 3 步：逐份抽取

```bash
python scripts/batch_extract.py <W>/manifest.json <W>/extracted
```

脚本会遍历清单里的**全部**文件（pdf 与 docx 都处理），逐份生成
`<序号>_<姓名>/content.md`（正文，含页码标记）和 `images/`（正文中的全部图片，含实验结果截图）。
图片在 `content.md` 里以 `![](images/xxx.png)` 标注在对应位置。

**不要手动逐份调 `extract.py`**，统一用 `batch_extract.py`，避免混入 docx 的作业被漏抽。

### 第 4 步：逐份批改

对每份作业：

1. 读 `content.md`，对照 `rubric.json` 逐项判分
2. **遇到 `![](...)` 就用 Read 工具打开对应图片看**——运行结果截图、流程图、程序界面截图都只能从这里判断，不要因为看不到图就跳过该项
3. 写 `W/grades/<序号>.json`

```json
{
  "filename": "2023001_张三.docx",
  "items": [
    {"title": "实验目的", "anchor": "1. 实验目的", "score": 4, "max": 5, "comment": "未结合本次任务"},
    {"title": "功能模块结构图", "anchor": "4.1.1 主要功能模块结构图", "score": 13, "max": 15, "comment": "缺少交互说明"}
  ],
  "total": {"score": 92, "max": 100},
  "notes": ""
}
```

硬性要求：

- `anchor` **必须原样抄作业里那道题的标题文本**（不是 rubric 里的措辞）。PDF 靠它在页面上定位落笔位置，抄错就写不上去。学生写"一、实验目的"就填"一、实验目的"。
- 每个评分点都要有 `score`，包括 0 分。
- `comment` 控制在 14 字以内（PDF 只落短批注），没有就不填。
- 同一处缺陷只在一个评分点扣一次，不在多个分项重复扣。
- `notes` 用于标记"文件损坏""扫描件无法识别""明显抄袭"等异常。

### 第 5 步：落笔

```bash
# PDF：题号左侧白边写手写红分数，末页右下写总分
python scripts/annotate_pdf.py <grades json> <原PDF> <W>/result/<文件名>

# Word：题目标题末尾追加红色分数，文末追加总分
python scripts/annotate_docx.py <grades json> <原docx> <W>/result/<文件名>
```

输出里的"未定位"警告要记下来，说明该题分数没写上去，需在汇总里提示教师人工补。

### 第 6 步：统计表

```bash
python scripts/make_excel.py <W>/grades <W>/批改统计.xlsx
```

总分由脚本按分项相加重算，模型给的总分只做核对。

### 第 7 步：共性问题

写 `W/共性问题.md`，包含：

1. **最集中的 3-5 个问题**：每个问题说明具体表现
2. **涉及面**：多少份作业出现（比例）
3. **改进建议**：针对每个问题给一条可操作的教学建议

结论必须来自实际批改记录，能对应到具体作业。

## 批改原则

- **按表给分**：严格用 `rubric.json` 的分值，不自行增减评分点，不因整体印象给"印象分"。
- **有据可依**：每处扣分要指向作业中的具体内容（缺哪一段、哪张图、代码哪一处不对）。
- **看图为证**：评分点涉及运行结果、界面效果、流程图时，必须看到图片再判分；图片打不开就判该项存疑，在 `notes` 说明，不臆断。
- **分数粒度**：整数或 0.5。
- **不跨项重复扣分**：同一问题只扣一次。

## 限制

- 只处理 `.docx` / `.pdf`；`.doc`、`.wps` 等旧格式在 `prepare.py` 阶段被跳过并列入 `skipped`。
- 不支持扫描件/图片型 PDF（无文字层，无法定位题号），会在抽取阶段暴露为正文为空，需在汇总里标记人工批改。
- 一次批改数量建议不超过 60 份，避免上下文超限；超过时分批跑，最后合并 `grades/` 目录再统一生成 Excel。
